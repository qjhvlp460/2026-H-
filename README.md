## 1. 项目概述

本系统为2026年全国大学生电子设计竞赛（TI杯）H题"车载平衡滚球运动控制系统"的完整解决方案。系统由两大部分组成：STM32F103C8T6控制的循迹小车底盘，以及基于瑞芯微泰山派（Linux SBC）的视觉钢球位置检测系统。两板之间通过USB转TTL串口模块进行单向数据通信，泰山派将钢球在摆杆凹槽中的实时像素坐标发送至STM32，STM32运行比例控制算法驱动舵机调整摆杆倾角，使钢球始终稳定在摆杆中心附近。

### 1.2 数据流

```
摄像头 → 泰山派cv2读取 → LAB色彩空间球检测 → 坐标平滑滤波
    → 串口发送 (x,y,r,status) → STM32 USART3接收中断
    → P控制器计算舵机角度 → TIM4 PWM输出 → DS3230舵机驱动摆杆
```

### 1.3 控制原理

摆杆左端铰链固定于小车平板上方（高度h≥5cm），右端通过连杆连接舵机摇臂。舵机旋转带动摆杆右端升降，使摆杆产生倾斜角。钢球在重力作用下沿凹槽滚动。摄像头固定在凹槽正上方，实时捕获钢球位置。STM32计算球位置与中心点的偏差，输出舵机角度修正量，形成闭环负反馈控制：

```
球偏右 → 舵机使摆杆右端升高（左倾） → 球向左滚回
球偏左 → 舵机使摆杆右端降低（右倾） → 球向右滚回
```

## 2. 硬件平台介绍

### 2.1 STM32F103C8T6 最小系统板

STM32F103C8T6是基于ARM Cortex-M3内核的32位微控制器，属于意法半导体公司的STM32F1系列中密度产品线。其主要参数如下：

| 参数 | 数值 |
|---|---|
| 内核 | ARM Cortex-M3, 32-bit |
| 最高主频 | 72 MHz |
| Flash存储器 | 64 KB |
| SRAM | 20 KB |
| 封装 | LQFP48 (48引脚) |
| 工作电压 | 2.0V ~ 3.6V（典型3.3V） |
| GPIO数量 | 37个可用IO口 |
| 定时器 | 3个通用定时器（TIM2/TIM3/TIM4）+ 1个高级定时器（TIM1） |
| USART | 3个（USART1/USART2/USART3） |
| I2C | 2个 |
| SPI | 2个 |
| ADC | 2个12位ADC，共10个通道 |
| 调试接口 | SWD (Serial Wire Debug)，占用PA13(SWDIO)和PA14(SWCLK) |

**为什么选择F103C8T6？**

F103C8T6是电子设计竞赛中最经典的单片机选型，原因如下：
- 性能足够：72MHz主频处理5路灰度传感器采样、电机PWM控制、舵机PWM生成、串口中断接收、PID运算，完全胜任。
- 生态成熟：Keil MDK-ARM开发环境、STM32标准外设库（StdPeriph Lib）v3.5.0，网上资料极其丰富。
- 引脚兼容：LQFP48封装提供37个GPIO，本系统使用了23个，仍有14个空闲供扩展。
- 价格低廉：最小系统板（含晶振、复位电路、LDO、MicroUSB）通常只要十元左右。

**引脚编号规则说明**

STM32F103C8T6采用LQFP48封装，芯片上有一个小圆点标记引脚1的方向。引脚编号从1到48逆时针排列（俯视，小圆点在左下角）。在代码中我们使用`GPIOA`、`GPIOB`、`GPIOC`加引脚编号来指代每个IO口。例如`GPIO_Pin_6`配合`GPIOB`表示芯片的第42脚（PB6）。

**GPIO端口分布**

| 端口 | 引脚范围 | 说明 |
|---|---|---|
| GPIOA | PA0~PA15 | 主要用作电机控制（PWM+方向） |
| GPIOB | PB0~PB15 | 灰度传感器、OLED I2C、按键、舵机、串口 |
| GPIOC | PC13~PC15 | RTC晶振引脚，一般不做GPIO使用 |
| PA13/PA14 | 调试口 | SWDIO/SWCLK，务必保留不可挪用 |

### 2.2 泰山派（Rockchip Linux SBC）

泰山派是基于瑞芯微RK3566（或类似Rockchip SoC）的国产单板计算机，运行Linux操作系统。本系统使用它的USB摄像头接口和USB转串口功能。

| 参数 | 说明 |
|---|---|
| SoC | Rockchip RK3566（四核ARM Cortex-A55） |
| RAM | 2GB/4GB DDR4 |
| 存储 | 32GB eMMC / TF卡 |
| OS | Debian/Ubuntu Linux |
| 40PIN排针 | 兼容树莓派引脚排列 |
| USB | 多个USB 2.0/3.0接口 |
| 网络 | 千兆以太网 + WiFi |
| SPI | 用于ST7789 LCD屏幕（可选） |
| GPIO | python-periphery库操作 |

**为什么用泰山派而不是OpenMV？**

题目要求摄像头上传画面能覆盖整个摆杆、清晰显示钢球滚动轨迹、判定钢球位置、完整记录测试视频并能回放。OpenMV虽然也是视觉模组，但它的分辨率和处理能力难以同时实现高清录制+实时推流+复杂图像处理。泰山派运行完整Linux，可以使用OpenCV的全部功能，同时通过ffmpeg录制视频、通过HTTP实时推流，性能远超OpenMV。而且泰山派有40PIN排针，可以连接各种外设。

### 2.3 USB摄像头

本系统使用普通的USB UVC摄像头（USB Video Class标准设备），在Linux下免驱动即插即用。关键选型要求：

| 参数 | 要求 | 原因 |
|---|---|---|
| 分辨率 | 至少640×480 | 摆杆检测需要足够像素 |
| 帧率 | 至少30fps，推荐60fps | 高帧率减少控制延迟 |
| 焦距 | 可调焦 | 固定焦距可能拍不清凹槽 |
| 视场角 | 约60~90度 | 覆盖25cm摆杆 |
| 安装方式 | 需有固定孔或可绑扎 | 固定在摆杆上方 |

摄像头通过USB线缆直接插入泰山派的USB接口，在Linux下显示为`/dev/video*`设备节点。本代码通过OpenCV的V4L2后端打开摄像头（`cv2.VideoCapture(index, cv2.CAP_V4L2)`），默认使用摄像头索引9，用户需根据实际设备调整。

### 2.4 电机驱动模块

本系统使用H桥电机驱动模块（常见型号如L298N、TB6612、MX1508等）。驱动模块接收STM32的PWM信号和方向信号，输出驱动电压给直流电机。

**L298N的特点：**
- 双H桥，可同时驱动两个直流电机
- 逻辑电压5V，驱动电压5V~35V
- 每通道持续电流2A
- 方向控制：IN1/IN2两个引脚控制一个电机的正反转
- 使能控制：ENA/ENB接收PWM信号控制电机转速

**接线逻辑：**
- IN1=1, IN2=0 → 电机正转
- IN1=0, IN2=1 → 电机反转
- IN1=IN2=0 或 IN1=IN2=1 → 电机停止（刹车）
- ENA PWM占空比 → 转速（0~99对应0%~99%）

### 2.5 5路灰度传感器

灰度传感器（又称红外循迹模块）通过红外发射管发射红外光，经地面反射后由红外接收管接收。黑色表面吸收红外光，白色表面反射红外光，因此传感器可以区分黑白。

| 参数 | 说明 |
|---|---|
| 工作电压 | 3.3V ~ 5V |
| 输出类型 | 数字量（TTL电平），黑线输出1（高电平），白底输出0（低电平） |
| 检测距离 | 约1~3cm（离地高度） |
| 数量 | 5个，横向排列 |
| 间距 | 约1.5~2cm（视黑线宽度1.8cm而定） |

**传感器编号定义（从小车前进方向看）：**

```
   L2   L1   M   R1   R2
   最左  略左  中  略右  最右
   PB12 PB11 PB13 PB14 PB15
```

**典型检测模式与含义：**

| L2 | L1 | M | R1 | R2 | 含义 | 动作 |
|---|---|---|---|---|---|---|
| 0 | 0 | 1 | 0 | 0 | 线在正中 | 直走 |
| 0 | 1 | 1 | 0 | 0 | 线偏左 | 左转 |
| 0 | 0 | 1 | 1 | 0 | 线偏右 | 右转 |
| 1 | 1 | 0 | 0 | 0 | 线大幅度偏左 | 左大拐 |
| 0 | 0 | 0 | 1 | 1 | 线大幅度偏右 | 右大拐 |
| 0 | 1 | 0 | 1 | 0 | 交叉线或特殊标记 | 触发特殊动作 |
| 0 | 0 | 0 | 0 | 0 | 丢线（全白） | 保持上一个状态 |

### 2.6 DS3230舵机

DS3230是一款270度大角度数字舵机，比常见的180度舵机（如SG90、MG996R）转动范围更大。这使其非常适合摆杆控制场景——摆杆需要较大的倾斜范围来产生足够的重力分量驱球滚动。

| 参数 | 数值 |
|---|---|
| 工作电压 | 4.8V ~ 7.2V |
| 堵转扭矩 | 约30kg·cm（7.2V时） |
| 转动角度 | 0° ~ 270° |
| 控制方式 | PWM 50Hz（周期20ms） |
| 脉宽范围 | 500μs（0°）~ 2500μs（270°） |
| 中间位置 | 1500μs（约135°） |
| 齿轮材质 | 金属齿轮 |
| 死区宽度 | 约3~5μs |

**PWM控制原理：**

舵机内部有一个电位器与输出轴联动，构成一个闭环位置伺服系统。控制电路接收PWM信号，测量高电平脉宽，将其转换为目标角度，并与当前电位器反馈的角度比较，驱动电机直到两者一致。

```
高电平500μs   → 目标角度0°（最左）
高电平1500μs  → 目标角度135°（中间，摆杆水平时通常在此附近）
高电平2500μs  → 目标角度270°（最右）
```

**重要：舵机供电警告**

舵机在堵转或大扭矩输出时瞬间电流可达3A以上，远超STM32板上LDO的输出能力（通常500mA）。如果舵机从STM32的5V引脚取电，会导致STM32瞬间掉电复位。因此舵机必须独立供电（从电池直接取电），但GND必须与STM32的GND共地，否则PWM信号无法形成完整回路。

| 参数 | 说明 |
|---|---|
| 分辨率 | 128×64像素 |
| 驱动芯片 | SSD1306 |
| 接口 | I2C（软件模拟） |
| I2C地址 | 0x78 |
| 尺寸 | 0.96英寸（≤2英寸，符合赛题要求） |
| 引脚 | SCL(PB8), SDA(PB9) |

OLED在本系统中显示运行时间、球位置像素坐标、系统状态等信息。

### 2.8 按键

系统使用一个轻触按键（KEY1），连接至PB5，按下时引脚电平拉低到GND。软件层面通过20ms延时消抖，并等待按键释放后返回键值。主程序启动后等待用户按下KEY1才开始行驶。

### 2.9 USB转TTL串口模块

该模块的核心芯片通常是CH340G或CP2102。它通过USB接口连接泰山派，在泰山派上枚举为`/dev/ttyUSB0`设备节点。TTL侧的TXD引脚连接到STM32的PB10引脚（USART3半双工模式），GND共地。

**注意电平匹配：** 模块通常有3.3V/5V电平选择跳线帽，务必选择3.3V档位。因为STM32的IO口耐压为3.6V（非5V容忍引脚为3.3V），5V电平会烧毁STM32的GPIO。

### 2.10 电源系统

竞赛规则要求小车由车载电池供电，不得外接电源。电源方案建议：

```
电池组（7.4V锂电池 / 12V锂电池）
    │
    ├──→ 电机驱动板电源输入端（直接连电池）
    │     └── 驱动板输出 → 两个直流电机
    │
    ├──→ 舵机电源线（红/棕）直接连电池
    │     （舵机工作需要5~7.4V，7.4V锂电池正好适用）
    │
    └──→ 降压模块（DC-DC，7.4V→5V）
          │
          ├──→ STM32最小系统板5V引脚（板载AMS1117降压为3.3V）
          │
          ├──→ 5路灰度传感器VCC
          │
          ├──→ USB转TTL模块VCC（或由USB口供电）
          │
          └──→ OLED模块VCC（如支持5V输入，否则接STM32板的3.3V）
```

**共地原则：** 所有模块的GND必须连接在一起（电池负极、驱动板GND、STM32 GND、舵机GND、传感器GND、USB转TTL GND、泰山派GND），形成统一的参考地平面。如果GND不共地，数字信号的高电平没有参考基准，会导致通信失败甚至损坏器件。

## 4. 机械结构搭建教程

### 4.1 摆杆制作

摆杆由4分PPR水管改造而成。PPR水管外径约2cm，壁厚0.34cm，内径约1.32cm，正好容纳直径1cm的钢球。

**步骤一：切割水管**

截取长度为25cm的一段PPR水管。两端打磨平整，去除毛刺。

**步骤二：开凹槽**

沿水管轴线方向切割出凹槽。推荐方法：
- 用台锯或钢锯沿水管长度方向切割一道缝
- 切割深度：约0.8~1cm（超过水管半径的一半，露出内壁但不切断）
- 切割宽度：刚好大于钢球直径（1cm），约1.1~1.2cm宽，保证钢球能自由滚动但不掉出
- 切割后打磨凹槽内壁使其光滑（赛题要求内壁光滑保持原状，不能有凹坑或增摩擦处理）

**步骤三：贴刻度线**

在凹槽边沿外侧（不是凹槽内部！）贴上刻度线，用于人工读出钢球位置。刻度间距0.1cm（即1mm），总长25cm覆盖整根摆杆。可以用激光打印机在透明胶片上打印刻度尺，剪下后贴在摆杆侧面。

**步骤四：安装铰链**

在摆杆左端底部安装金属合页（铰链），合页另一侧固定在小车底盘上。合页安装高度h≥5cm（从合页转轴到小车平板的垂直距离）。可以用小木块或亚克力垫块抬高合页安装点。

**步骤五：连接舵机**

摆杆右端钻孔或安装挂钩，通过连杆连接至舵机摇臂。连杆长度需根据舵机安装位置计算，保证舵机在中位时摆杆水平。建议使用可调长度的球头拉杆，方便微调。

### 4.2 传感器安装

**灰度传感器：** 5个传感器安装在小车底盘前部，横向排列，离地高度1~3cm。传感器间距建议1.8~2cm（适配1.8cm黑线宽度）。用L形支架或3M胶固定。

**摄像头：** 通过支架固定在摆杆正上方，镜头向下垂直拍摄。画面必须覆盖整个25cm摆杆凹槽，图像中钢球清晰可见。摄像头到摆杆距离约15~25cm（取决于镜头焦距），可通过实际画面调整。支架必须稳固，行驶中不能晃动。

**OLED：** 安装在容易观察的位置（如车顶或侧面），方便裁判查看时间显示。

### 4.3 重心与平衡

小车的物理重心对动态性能有决定性影响：
- 重心越低越稳定，但太低会增加轮距内的重量转移
- 电池建议放在底盘中央偏后
- 摆杆+舵机+摄像头在上方，重心会偏高，需要底盘配重（如在底盘加铅块/钢条）
- 摆杆机构总重尽量轻，减轻舵机负担

### 5.2 电机接线（以L298N为例）

```
L298N模块：
    12V输入    ← 电池正极
    GND        ← 电池负极 + STM32 GND
    5V输出     → (可选，给STM32供电，但不推荐同时用)
    
    ENA        ← STM32 PA2 (TIM2_CH3 PWM信号)
    IN1        ← STM32 PA5 (左轮正反转方向1)
    IN2        ← STM32 PA4 (左轮正反转方向2)
    OUT1       → 左电机接线柱
    OUT2       → 左电机接线柱
    
    ENB        ← STM32 PA1 (TIM2_CH2 PWM信号)
    IN3        ← STM32 PA7 (右轮正反转方向1)
    IN4        ← STM32 PA6 (右轮正反转方向2)
    OUT3       → 右电机接线柱
    OUT4       → 右电机接线柱
```

**逻辑表：**

| IN1 | IN2 | ENA PWM | 电机状态 |
|---|---|---|---|
| 1 | 0 | 0~99 | 正转，速度=占空比 |
| 0 | 1 | 0~99 | 反转，速度=占空比 |
| 1 | 1 | X | 刹车 |
| 0 | 0 | X | 自由停止 |
| X | X | 0 | 停止（不管IN状态） |

### 5.3 舵机接线

```
DS3230舵机引出线（标准三线）：
    棕色/黑色 → GND（电池负极，同时接STM32 GND）
    红色      → VCC（电池正极 5~7.4V）⚠️ 绝不可接STM32的3.3V/5V
    橙色/黄色 → 信号线 → STM32 PB6 (TIM4_CH1)
```

**为什么不可从STM32取电？**

STM32最小系统板的LDO（通常是AMS1117-3.3V）最大输出电流约800mA，而DS3230在堵转时电流可超3A。瞬间大电流会导致STM32供电电压跌落，触发欠压复位（BOR），程序重启。此外，舵机电机是感性负载，换向时会产生反向感应电动势，如与STM32共用电源会通过电源线耦合噪声到单片机，可能导致ADC读数不准或GPIO误触发。

### 5.4 灰度传感器接线

```
5路灰度传感器模块（通常有VCC/GND/OUT三排引脚）：
    VCC ← 3.3V或5V（视具体模块，常见5V供电3.3V输出）
    GND ← STM32 GND
    OUT1 ← STM32 PB11 (L1)
    OUT2 ← STM32 PB12 (L2)
    OUT3 ← STM32 PB13 (M)
    OUT4 ← STM32 PB14 (R1)
    OUT5 ← STM32 PB15 (R2)
```

灰度传感器输出是数字量：检测到黑线时输出高电平（逻辑1），检测到白色背景时输出低电平（逻辑0）。这是因为黑线吸收红外光，接收管截止，输出被上拉电阻拉到高电平；白色表面反射红外光，接收管导通，输出被拉低。

代码中通过`GPIO_ReadInputDataBit(GPIOB, Pin)`读取对应引脚的电平值。注意GPIO模式配置为IPU（输入上拉），这样可以在传感器输出不确定时保持高电平。

### 5.5 OLED接线

```
SSD1306 0.96寸 I2C OLED（4针脚）：
    VCC ← 3.3V
    GND ← STM32 GND
    SCL ← STM32 PB8
    SDA ← STM32 PB9
```

I2C地址为0x78（SA0引脚接地时的地址）。采用软件模拟I2C协议，GPIO配置为开漏输出（GPIO_Mode_Out_OD），通过置位和复位GPIO实现起始、停止、应答、数据发送等时序。

**SSD1306初始化流程（固件层面）：**
1. 关闭显示（0xAE）
2. 设置时钟分频/振荡器频率（0xD5, 0x80）
3. 设置多路复用率（0xA8, 0x3F）—— 64行
4. 设置显示偏移（0xD3, 0x00）
5. 设置显示起始行（0x40）
6. 设置段重映射（0xA1）—— 左右正常
7. 设置COM扫描方向（0xC8）—— 上下正常
8. 设置COM引脚配置（0xDA, 0x12）
9. 设置对比度（0x81, 0xCF）
10. 设置预充电周期（0xD9, 0xF1）
11. 设置VCOMH取消选择电平（0xDB, 0x30）
12. 设置显示模式（0xA4）
13. 设置正常/反转显示（0xA6）
14. 使能电荷泵（0x8D, 0x14）
15. 开启显示（0xAF）

### 5.6 按键接线

```
KEY1：
    一端 → STM32 PB5
    另一端 → GND

配置：GPIO_Mode_IPU（输入上拉）
原理：未按下时，PB5被内部上拉电阻拉到高电平（逻辑1）
      按下时，PB5被短接到GND，读到低电平（逻辑0）
      软件消抖：读到低电平后延时20ms再读一次，确认真实按下
```

### 5.7 串口接线

```
USB转TTL模块：
    USB接头  → 泰山派USB口
    VCC      → (可选) 由USB供电或外部5V
    GND      → STM32 GND（共地）
    TXD      → STM32 PB10
    RXD      → 不接（目前单向通信，泰山派→STM32）
    3.3V跳线 → 必须置于3.3V档位（不是5V！）
```

在STM32侧，PB10配置为USART3的TX引脚，启用半双工模式（USART_HalfDuplexCmd）。半双工模式下，USART3仅使用TX引脚进行单向或双向通信，RX引脚（PB11）被释放出来，PB11正好用作灰度传感器L1。

```python
frame = frame[120:360, 170:470]  # 从640×480原图裁剪出240×300区域
```

`[120:360, 170:470]`表示取原图的第120行到第360行（共240行）、第170列到第470列（共300列）。这个区域应该恰好覆盖整个摆杆凹槽范围。用户需要根据实际摄像头安装位置调整这四个参数。调整方法是：

1. 将钢球放在摆杆最左端和最右端，观察摄像头画面
2. 确保两个极端位置都在裁剪区域内
3. 左右留少量余量（约20~50像素）
4. 上下裁剪到刚好包含凹槽

### 6.4 LAB色彩阈值标定

钢球是银色金属球，在不同光照下颜色表现差异巨大。LAB色彩空间将亮度和颜色信息分离，比RGB更适合光照变化大的检测场景。

运行标定工具：

## 7. 系统通信架构

### 7.1 通信链路

```
[USB摄像头] --V4L2--> [泰山派 OpenCV] --Python serial--> [/dev/ttyUSB0]
    --USB线--> [USB转TTL CH340G] --TXD(PB10)--> [STM32 USART3半双工]
    --RXNE中断--> [环形缓冲区] --解析--> [BallData_t结构体]
    --主循环读出--> [P控制器] --Servo_SetAngle--> [TIM4_CH1 PWM] --PB6--> [舵机]
```

### 7.2 串口参数

| 参数 | 值 | 说明 |
|---|---|---|
| 波特率 | 115200 bps | 高速率保证数据及时传输 |
| 数据位 | 8 bit | 每帧8位数据 |
| 停止位 | 1 bit | 标准1位停止位 |
| 校验位 | None | 不校验，通过数据格式自检 |
| 流控 | None | 无需硬件流控 |
| 传输模式 | USART3 Half-Duplex | 单线半双工，仅用PB10 |

### 7.3 数据格式

泰山派每一帧检测结果通过串口发送一条消息：

```
格式：cx,cy,r,status\n

示例：152,118,15,1\n

字段说明：
    cx     - 钢球中心X坐标（像素，ROI坐标系，范围约0~300）
    cy     - 钢球中心Y坐标（像素，范围约0~240）
    r      - 钢球半径（像素，范围约4~70）
    status - 检测状态：0=丢失, 1=完整圆, 2=半圆
    \n     - 换行符（帧结束标志）
```

STM32的USART3中断服务程序逐字节接收，遇到换行符`\n`时认为一帧数据完整，调用`sscanf`将字符串解析为四个整型字段存入`BallData_t`结构体。

### 7.4 超时与安全保护

STM32主循环每秒检查一次数据新鲜度。如果超过1秒未收到新的球坐标数据（`time - ball_data.last_rx_time > 1`），自动将舵机恢复到中立角度（`SERVO_NEUTRAL`），避免因通信中断导致舵机卡在极限位置烧毁电机。这个超时保护至关重要——实际测试中可能因为USB松动、泰山派死机、摄像头掉线等原因导致数据流中断。

### 7.5 MJPEG网页推流（要求1实现基础）

`xbhdcc_tools.py`实现了一个多线程HTTP服务器，将检测画面实时推送为MJPEG流。在任意设备的浏览器中打开`http://泰山派IP:8081`即可看到双路画面：
- 通道0：标注了检测结果的原始画面（带圆、十字线、坐标、FPS）
- 通道1：黑白二值mask画面（用于调试阈值）

这是赛题"要求1"（摆球位置监测图传装置）的基础实现。后续可以增加无线网卡改为WiFi图传，并使用ffmpeg录制视频流到本地文件，实现"完整记录钢球运动视频且能回放"的功能。

### 8.3 循迹状态机（Walk.c）

循迹采用**有限状态机（FSM）**架构，将5个传感器值映射为运动状态：

```
状态枚举：
  FORWARD(10)      直走
  LEFT_TURN(11)    左拐小弯
  LEFT_Big_TURN(12)左大拐
  RIGHT_TURN(13)   右拐小弯
  RIGHT_Big_TURN(14)右大拐
  STOP(15)         停止
  FORWARD_RUSH(16) 冲刺
  ACUTE_LEFT(17)   锐角左弯
  ACUTE_RIGHT(18)  锐角右弯
```

**Walk_Judge判断逻辑（优先级从高到低）：**

1. **丢线判断**：全部5路传感器都为0（全白）→ 启用Last_State保持上次状态
2. **锐角弯**：L2+L1同时为1（最左两路）或R1+R2同时为1（最右两路），且全局时间time>54秒（比赛后半程特征路段）→ ACUTE_LEFT/RIGHT
3. **特殊标记**：L1+R1同时为1但M=0 → 特定路口，时间>54秒触发
4. **大拐弯**：最外侧传感器单独为1，中间传感器为0 → LEFT/RIGHT_Big_TURN
5. **小拐弯**：略偏传感器（L1或R1）为1 → LEFT/RIGHT_TURN
6. **直走**：仅中间传感器M为1 → FORWARD

**Last_State状态保持机制：**

当传感器全部读到0（丢线）时，代码返回上一次有效的状态（Last_State）而非停止。这解决了两个问题：
- 在黑白交界处暂态丢失时的抖动
- 黑线宽度稍有变化时的短暂脱线

但Last_State也有副作用：如果小车完全偏离轨道（物理上脱离黑线），它会继续保持上一个方向运动，越走越远。因此必须结合赛道实际测试调整传感器的灵敏度和安装高度。

**Timer反误触机制：**

全局变量NUM和time由TIM3每秒中断增量一次。传感器读取时检查`NUM>=1`，锐角弯检测后将NUM清零，这意味着进入锐角弯后至少1秒内不会再次触发锐角弯检测，防止传感器在锐角弯不同位置反复切换状态导致抖动。

time>54的条件用于区分赛道不同阶段：比赛前半程（54秒内）不会触发锐角弯和特殊路段逻辑，后半程（54秒后）才会启用。这需要根据实际赛道和行驶时间调整阈值。

### 8.4 电机控制（Motor.c）

采用**差速转向**策略：

```c
#define WALK_SPEED 30    // 基准速度(占空比30/100=30%)
#define ADJUST 20        // 转向调节量

直走：     左=30, 右=30
左拐小弯： 左=30-20=10, 右=30+20=50  （左轮减速，右轮加速）
右拐小弯： 左=30+20=50, 右=30-20=10
左大拐：   左=-10,      右=30+20=50  （左轮倒转）
右大拐：   左=30+20=50, 右=-10        （右轮倒转）
锐角左弯： 左=-30,      右=50        （左轮更强倒转）
锐角右弯： 左=50,       右=-30
冲刺：     左=50, 右=50               （全速前进）
停止：     左=0,  右=0
```

**PWM配置：**

TIM2时钟源为72MHz，经过720分频后得到100kHz的计数频率，自动重装值ARR=100-1，即PWM周期=100μs×100=10ms，频率=100Hz。占空比寄存器CCR的范围0~99对应0%~99%的功率输出。

### 8.5 舵机控制（Servo.c）

TIM4时钟源72MHz，经过72分频后得到1MHz的计数频率（1μs精度）。自动重装值ARR=20000-1，PWM周期=20000μs=20ms，频率=50Hz，完美匹配舵机标准。

```c
角度→脉宽计算：
pulse_us = 500 + angle * 2000 / 270

Servo_SetAngle(0)   → pulse = 500μs  (0°)
Servo_SetAngle(135) → pulse = 1500μs (中间)
Servo_SetAngle(270) → pulse = 2500μs (270°)
```

### 8.6 串口接收（UART3.c）

USART3配置为半双工单线模式，波特率115200bps。中断服务函数USART3_IRQHandler在RXNE（接收寄存器非空）事件触发时被调用。

**接收流程：**
1. 硬件接收一个字节→RXNE标志置位→触发中断
2. 中断函数读出字节→若为`\n`则结束一帧，调用`parse_ball_data()`解析
3. 解析使用`sscanf(str, "%d,%d,%d,%d", &cx, &cy, &r, &st)`提取四个整数值
4. 若status>0（有效检测），将数据写入全局`ball_data`结构体，设置fresh标志
5. fresh标志由主循环轮询检查和清零

**为什么用中断而非轮询？**

如果使用轮询方式（在主循环中每次检查USART标志位），当主循环因循迹判断和电机控制消耗较长时间时，可能错过串口接收的字节。115200bps下每字节传输间隔仅约87μs，轮询方式极易丢字节。中断方式将接收任务交由硬件和中断服务程序处理，主循环只在需要时读取最新结果，实现了异步解耦。

### 8.8 钢球检测算法详解（ball_detect.py）

BallDetector类实现了完整的钢球检测管线，专为金属反光球体设计：

**步骤一：LAB色彩空间转换**

OpenCV读取的BGR图像首先转换为LAB色彩空间。LAB的三个通道含义：
- L通道：亮度（0~255），0为黑色，255为白色
- A通道：绿→红（-128~127），负数偏绿，正数偏红
- B通道：蓝→黄（-128~127），负数偏蓝，正数偏黄

银色金属球的特性是L值中等偏高（较亮），A和B值接近0（中性灰色）。因此阈值范围设定在L:25~55, A:-10~10, B:-10~10附近。

**步骤二：双掩码策略**

金属球的核心问题是镜面反光——球面弯曲导致只有一小块区域反射光线到摄像头，球的其他部分呈暗色，在单阈值二值化下呈现出"空心圆环"而非"实心圆盘"。本算法创新性地使用双层掩码：

1. **亮球掩码**：捕获球面反射的高亮区域
2. **阴影掩码**：捕获球底部在凹槽中产生的阴影（L值偏低）

两者进行按位或（bitwise_or）合并，理论上得到一个近似完整的圆形区域。

**步骤三：形态学处理**

形态学操作是二值图像处理的核心工具：
- **开运算（先腐蚀后膨胀）**：去除孤立的白色噪点。核大小3×3
- **闭运算（先膨胀后腐蚀）**：填充白色区域内的黑色空洞（如反光造成的球心空洞）。核大小11×11（大核是关键！）
- **两次闭运算**：先合并球体碎片，再连接球体与阴影

**步骤四：连通域面积滤波**

计算合并mask中所有连通域的面积，过滤掉：
- 面积<50像素的：环境噪点
- 面积>3500像素的：大块背景干扰
- 只保留面积最大的前3个连通域

**步骤五：轮廓分析与评分**

对每个候选连通域提取轮廓，计算多维特征：
- **圆形度** `circularity = 4π×面积/周长²`：理想圆为1.0，越不规则越低
- **实心度** `solidity = 轮廓面积/凸包面积`：有空洞时<1.0
- **宽高比** `aspect = min(宽,高)/max(宽,高)`：正方形为1.0
- **综合评分** `score = 0.4×circularity + 0.3×solidity + 0.3×aspect`

选择评分最高的候选轮廓为最终检测结果。

**步骤六：半圆检测**

当圆形度低于阈值（0.40）但宽高比>0.5且实心度在0.3~0.8之间时，判定为半圆（球被部分遮挡或严重反光）。此时：
- 使用凸包（convexHull）的矩来计算中心（比轮廓矩更稳定）
- 从面积反推半径：`r = sqrt(2×面积/π)`

半圆检测的评分乘以0.85折扣，但依然可以参与候选竞争。

**步骤七：多帧闪烁过滤**

维护一个3帧的候选缓冲区。计算缓冲区内所有候选位置的X和Y坐标的极差（spread = max-min）。如果极差超过30像素，说明检测结果在相邻帧之间剧烈跳变（可能是环境噪点造成的误检），清空缓冲区并拒绝本次检测。

**步骤八：丢帧恢复**

允许最多连续8帧丢失（约0.13秒@60fps）。如果超过8帧仍未检测到球，将valid_center清零。重新检测到球时，清空滤波器的历史缓冲区，防止旧的位置数据污染新的跟踪。

**步骤九：滑动平均滤波**

MovingAvgFilter类维护一个长度为5的窗口，对连续5帧的X、Y、R坐标取算术平均。这有效抑制了检测结果的随机抖动，输出更平滑的轨迹给STM32控制。

### 8.10 定时器资源分配

STM32F103C8T6有4个定时器，本系统使用了3个：

| 定时器 | 通道/用途 | 引脚 | 频率 | 说明 |
|---|---|---|---|---|
| TIM2 | CH2 | PA1 | 100Hz | 右轮PWM |
| TIM2 | CH3 | PA2 | 100Hz | 左轮PWM |
| TIM3 | 中断 | — | 1Hz | 全局秒计数器(NUM, time) |
| TIM4 | CH1 | PB6 | 50Hz | 舵机PWM信号 |
| SysTick | 延时 | — | — | Delay_us/ms/s函数 |

TIM2的CH1（PA0）和CH4（PA3）在改为两驱后已被释放。如果后续需要添加其他PWM控制（如额外的伺服），可以使用这两个通道。

## 11. 通讯协议规范

### 11.1 物理层

| 参数 | 规范 |
|---|---|
| 接口标准 | UART TTL (3.3V CMOS) |
| 连接方式 | 单线半双工 |
| 信号线 | PB10 (USART3_TX, 复用为收发) |
| 空闲电平 | 高电平 (逻辑1) |
| 起始位 | 低电平1bit |
| 数据位 | 8bit, LSB先发 |
| 停止位 | 高电平1bit |

### 11.2 数据链路层

| 参数 | 规范 |
|---|---|
| 波特率 | 115200 bps |
| 帧头 | 无 |
| 帧尾 | `\n` (0x0A) |
| 帧长 | 可变，约11~16字节 |
| 校验 | 无硬件校验，依赖格式自检 |
| 最大帧率 | 约60fps（与摄像头帧率同步） |
| 超时 | 1000ms无数据→舵机归位 |

### 11.3 应用层数据包定义

```
字段1: cx (int)    - 钢球中心X坐标，像素值，范围0~300
字段2: cy (int)    - 钢球中心Y坐标，像素值，范围0~240
字段3: r  (int)    - 钢球半径，像素值，范围4~70
字段4: st (int)    - 检测状态标志位

分隔符: 逗号 (,)
结束符: 换行符 (\n)

示例数据包：
  "150,120,15,1\n"    → 球在(150,120)，半径15px，完整圆
  "0,0,0,0\n"         → 球丢失
  "80,115,12,2\n"     → 球在(80,115)，半径12px，半圆检测
```

### 11.4 状态码定义

| status | 含义 | STM32行为 |
|---|---|---|
| 0 | 球丢失（未检测到） | 不更新ball_data（丢弃该帧） |
| 1 | 完整圆检测 | 正常更新ball_data，误差用于控制 |
| 2 | 半圆检测 | 正常更新ball_data，但标记为半圆模式 |

### 11.5 通信可靠性保障

1. **数据帧自同步**：以`\n`为帧边界，误码不会导致永久帧错位
2. **字段数量校验**：`sscanf`返回值检查确保4个字段解析成功
3. **status有效值校验**：status=0的数据包被丢弃（if(st>0)）
4. **超时看门狗**：1秒无数据→舵机归位，防止失控
5. **错误累积降级**：泰山派侧累计50次发送错误→切mock模式
6. **缓冲溢出保护**：接收缓冲区限制32字节，防止数组越界

## 12. 参数标定与调试流程

### 12.1 摆杆水平位标定

这是最关键的一步，关系到所有后续控制的准确性。

**步骤：**
1. 将钢球放在摆杆中心刻度0位置
2. 手动调整舵机连杆长度或舵机安装角度，使摆杆肉眼水平
3. 运行代码，在`main.c`中临时添加`Servo_SetAngle(90)`看看摆杆是否接近水平
4. 微调`SERVO_NEUTRAL`的值（每次加减5~10），观察摆杆实际倾角变化
5. 找到使摆杆恰好水平的舵机角度，记录为`SERVO_NEUTRAL`

### 12.2 摆杆中心像素标定

**步骤：**
1. 运行`ball_detect.py`，保证摄像头画面中能看到整个摆杆凹槽
2. 将钢球精确放在摆杆中心刻度0位置
3. 观察OLED上显示的球X坐标（px值），连续观察几秒取平均值
4. 将这个值填入`main.c`中的`ROD_CENTER_X`

### 12.3 Kp增益标定

比例增益`KP_BALL`决定了控制系统的响应强度。标定方法：

**步骤：**
1. 先从较小的Kp值开始（如0.05）
2. 在泰山派网页监控中观察球的运动
3. 用小棍手动将球拨离中心10cm左右，松手
4. 观察球的回中过程：
   - **Kp太小**：球回中很慢，甚至停在偏离位置不动
   - **Kp合适**：球迅速回中，略有1~2次超调振荡后稳定
   - **Kp太大**：球来回剧烈振荡，无法稳定
5. 二分法调整Kp直到回中迅速且无严重振荡

### 12.4 LAB阈值标定

**准备工作：** 将摄像头安装到最终位置，打开比赛场地的实际灯光。

**步骤：**
1. 运行`python3 lab_calibrate.py`
2. 浏览器打开 `http://泰山派IP:8081`
3. 将钢球放在凹槽内的不同位置（左、中、右），观察mask画面
4. 在终端中输入`b`进入亮球阈值调整模式：
   - 逐步调整L_min和L_max，使得明亮金属区域完整呈现为白色
   - 调整A_min/A_max/B_min/B_max，排除背景中的彩色噪点
5. 输入`s`进入阴影阈值调整模式：
   - 同样调整阈值，使得球底部阴影区域也呈现为白色
6. 观察合并mask中钢球是否完整（实心圆盘而非空心圆环）
7. 输入`save`保存阈值

**注意事项：**
- 标定时必须使用比赛现场的实际光照条件
- 如果赛场光线变化大，可适当放宽阈值（牺牲一些抗噪性能换取光照鲁棒性）
- 阴影阈值不是必须的，如果球颜色和背景对比度很高，可以不启用阴影检测

### 12.5 电机基准速度标定

`WALK_SPEED`和`ADJUST`的值决定了小车的行驶速度和转弯性能。

| 参数 | 默认值 | 调大效果 | 调小效果 |
|---|---|---|---|
| WALK_SPEED | 30 | 直道更快，但过弯易冲出轨道 | 速度慢，但更稳定 |
| ADJUST | 20 | 转弯更猛，适合急弯 | 转弯柔和，适合缓弯 |

建议在赛道上实际测试，找到一个平衡点：直道够快满足时间要求，弯道够稳不冲出轨道。

## 13. PID控制入门与调参

本系统目前实现了最基本的P（比例）控制。以下是扩展为完整PID控制器的教程。

### 13.1 控制回路分析

这是一个典型的**球-杆系统（Ball-on-Beam）**控制问题：

```
设定值(摆杆中心=0) → [Σ] → [PID控制器] → [舵机] → [摆杆倾角] → [球位置]
                        ↑                                       │
                        └────────── [摄像头测量] ←───────────────┘
```

被控对象（Plant）的动力学：
- 球在倾斜轨道上的加速度 a = g × sin(θ)，其中θ是摆杆倾角，g是重力加速度
- 球的位置 x 是加速度的二重积分：x = ∫∫ a dt²
- 这是一个**二阶积分系统**，天然存在不稳定倾向

### 13.2 P（比例）控制

```c
error = ball_data.x - ROD_CENTER_X;
angle = SERVO_NEUTRAL - KP_BALL * error;
```

比例控制根据当前误差大小调整输出。特点：
- **优点**：响应快，实现简单
- **缺点**：存在稳态误差（球可能稳定在偏离中心的某个位置而非精确中心）
- **适用场景**：对稳态精度要求不高的快速响应场景

### 13.3 PI（比例+积分）控制

```c
// 在main函数外声明静态变量
static float integral = 0.0f;

// 主循环中
error = ball_data.x - ROD_CENTER_X;
integral += error * DT;  // DT是控制周期（约0.005秒）
integral = clamp(integral, -INTEGRAL_MAX, INTEGRAL_MAX); // 积分限幅
angle = SERVO_NEUTRAL - KP_BALL * error - KI_BALL * integral;
```

积分项累积历史误差，可以消除稳态误差。特点：
- **优点**：消除稳态误差，球可以精确停在中心
- **缺点**：可能引起过冲和振荡；积分饱和（windup）需要在球丢失时清零积分
- **积分限幅**：防止积分值过大导致失控

### 13.4 PID（比例+积分+微分）控制

```c
static float prev_error = 0.0f;
static float integral = 0.0f;

error = ball_data.x - ROD_CENTER_X;
integral += error * DT;
integral = clamp(integral, -INTEGRAL_MAX, INTEGRAL_MAX);

float derivative = (error - prev_error) / DT;
angle = SERVO_NEUTRAL - KP_BALL * error - KI_BALL * integral - KD_BALL * derivative;
prev_error = error;

// 球丢失时清零积分
if (ball_data.status == 0) {
    integral = 0.0f;
}
```

微分项根据误差变化率预判未来趋势，起阻尼作用。特点：
- **优点**：抑制振荡，提高系统稳定性；对突变干扰有快速响应
- **缺点**：对测量噪声敏感（球的像素坐标会有高频抖动）
- **微分先行**：可以采用对测量值微分而非误差微分的策略减少冲击

### 13.5 调参口诀

PID三个参数的调试有一个经典的Ziegler-Nichols方法和一个更实用的试凑法：

**试凑法（现场调参最实用）：**

1. 先设Ki=0, Kd=0，只调Kp
2. 增大Kp直到球开始出现持续振荡（临界振荡点），记录此时的Kp值为Ku，振荡周期为Tu
3. 根据下表设置参数：

| 控制器类型 | Kp | Ki | Kd |
|---|---|---|---|
| P | Ku/2 | 0 | 0 |
| PI | Ku/2.2 | Kp/(Tu/1.2) | 0 |
| PID | Ku/1.7 | Kp/(Tu/2) | Kp×(Tu/8) |

4. 在实际测试中微调：
   - 球过冲太大 → 减小Kp，或增大Kd
   - 球回中太慢 → 增大Kp，或增大Ki
   - 球在中心附近来回抖动 → 增大Kd，或减小Kp
   - 球停在偏心位置不动 → 增大Ki

## 14. 赛道策略分析

### 14.1 赛道几何参数

根据赛题说明：
- 赛道为环形黑线，线宽1.8±0.2cm
- AB段：直线，长度1.5m
- BC段：半径为0.5m的半圆弧
- CD段：直线，长度1.5m
- DA段：半径为0.5m的半圆弧
- A点：起始终点位置，有5cm黑色启停线
- 小车尺寸限制：≤35cm×25cm

### 14.2 各要求任务分析

**要求2：循迹一圈停A点（16分，行驶时间≤20s，停车偏差≤2cm）**

这是纯循迹任务，不控球。策略：
- 计算赛道总长度：两条1.5m直线 + 两个半圆（半径0.5m，半圆周长=πr=1.57m）= 3m + 3.14m = 6.14m
- 要求20秒完成，平均速度≥0.307m/s，对循迹小车来说非常宽松
- 难点是精确停车：需要识别A点启停线，并精确控制刹车距离
- A点启停线是宽度1.8cm、长度5cm的垂直黑线，所有5路传感器会同时检测到1

**要求4：A→B控球平衡（20分，AB段≤8s，球误差≤1cm）**

首次引入控球。策略：
- AB段是1.5m直道，对循迹挑战不大
- 8秒跑完1.5m意味着均速≥0.1875m/s，也不紧张
- 全神贯注于球平衡：直道时摆杆扰动主要来自车体颠簸
- 电机加速/减速会引起车身俯仰，间接影响球的稳定

**要求5：整圈控球平衡（20分，≤30s，球误差≤1cm）**

这是对系统综合性能的全面考验：
- 30秒跑完6.14m，平均速度≥0.2m/s
- 直道段相对容易保持平衡
- 弧线段挑战最大：离心力会使球向外侧偏移，需要通过舵机向内补偿
- 弧线段的速度需要适当降低，给舵机更多时间响应

**要求6：任意位置控球（20分，≤30s，球误差≤1cm）**

这对控制精度提出最高要求：
- 球需要在指定的任意位置（如+10cm或-8cm）保持稳定
- 本质上是一个**给定跟踪**问题（setpoint tracking），而非仅回中（regulation）
- 代码实现：只需将`ROD_CENTER_X`改为用户指定的目标位置，P控制器会自动驱动球向新位置移动
- 如果只用P控制，球会停在偏离指定位置的某个稳定点（稳态误差），需要加I项消除

### 14.3 弯道补偿策略

在弯道行驶时，离心力会使钢球产生额外的侧向加速度。补偿方法：

**方法一：前馈补偿**

根据弯道方向预判补偿量：
```c
if (state == LEFT_TURN || state == LEFT_Big_TURN) {
    angle_compensation = -BEND_COMPENSATION;  // 左弯使球右偏，需要左倾补偿
} else if (state == RIGHT_TURN || state == RIGHT_Big_TURN) {
    angle_compensation = +BEND_COMPENSATION;
} else {
    angle_compensation = 0;
}
servo_angle = SERVO_NEUTRAL - KP_BALL * error + angle_compensation;
```

**方法二：增加微分项**

弯道带来的离心力突变可以用微分项捕捉：
```c
derivative = (error - prev_error) / DT;
angle += KD_BALL * derivative;  // 误差突然增大时，微分项快速响应
```

## 15. 常见故障排查

### 15.1 电机不转

| 可能原因 | 排查方法 |
|---|---|
| 电池没电 | 万用表测电池电压，低于6V需充电 |
| 驱动板未供电 | 测驱动板电源输入端电压 |
| PWM未输出 | 用示波器测PA1/PA2，确认有100Hz方波 |
| 方向引脚配置错误 | 检查IN1/IN2电平，正转应为一高一低 |
| 电机线断裂 | 用万用表通断档测电机两端电阻 |
| 代码占空比为0 | 检查WALK_SPEED值是否为0，或speed变量是否被意外清零 |

### 15.2 循迹不准/冲出轨道

| 可能原因 | 排查方法 |
|---|---|
| 传感器离地太高 | 降低传感器到1~3cm范围内 |
| 传感器灵敏度问题 | 模块上有可调电位器，旋转调整阈值 |
| 黑白对比度不够 | 黑线是否褪色？白底是否脏污？ |
| 速度太快 | 降低WALK_SPEED试试 |
| 环境光干扰 | 红外传感器受太阳光影响，室内光影响较小 |
| 丢线恢复逻辑失效 | 检查Last_State逻辑，打印传感器值到OLED调试 |

### 15.3 舵机不转或颤动

| 可能原因 | 排查方法 |
|---|---|
| 舵机供电不足 | 测舵机VCC电压，确保≥4.8V |
| 共地未接 | 舵机GND必须接STM32 GND |
| PWM配置错误 | 示波器测PB6，应有50Hz方波，脉宽500~2500μs |
| 信号线接错 | 确认是PB6而非其他引脚 |
| 舵机机械堵转 | 断开连杆，手动检查舵机摇臂转动是否顺畅 |
| 脉宽超范围 | 检查Servo_SetAngle参数，不超过0~270 |
| 主循环死循环 | 在while(1)中加断点或LED闪烁确认正常运行 |

### 15.4 串口无数据

| 可能原因 | 排查方法 |
|---|---|
| 波特率不匹配 | 两边都确认是115200 |
| TXD/RXD接反 | 交换TXD和RXD试试 |
| 电平不匹配 | 万用表测USB转TTL TXD空闲电平，应为3.3V |
| 串口设备节点不对 | `ls /dev/ttyUSB*` 确认设备名 |
| 权限不足 | `sudo chmod 666 /dev/ttyUSB0` |
| pyserial未安装 | `pip3 list | grep pyserial` |
| STM32半双工未启用 | 确认USART_HalfDuplexCmd已调用 |
| 摄像头未工作 | 确认ball_detect.py正常运行，网页能看到画面 |

### 15.5 OLED无显示

| 可能原因 | 排查方法 |
|---|---|
| I2C接线错误 | 确认PB8→SCL, PB9→SDA |
| VCC电压不对 | 测OLED VCC，应为3.3V |
| I2C地址错误 | 代码用的是0x78，有些模块是0x7A或0x3C |
| OLED未初始化 | 确认OLED_Init()被调用且在main之前 |
| 时序太快 | SSD1306驱动有时序要求，软件I2C可能需加Delay |

### 15.6 钢球检测不准确

| 可能原因 | 排查方法 |
|---|---|
| LAB阈值不对 | 运行lab_calibrate.py重新标定 |
| 环境光变化 | 比赛现场光线与标定时不同，需重新标定 |
| ROI裁剪不对 | 调整ROI范围确保覆盖整根摆杆 |
| 形态学核太大/太小 | 调整kernel_big大小（反光空洞大→加大核） |
| MIN_CIRC阈值太严 | 降低圆形度阈值（如从0.4降到0.3） |
| 摄像头分辨率太低 | 确保640×480且对焦清晰 |
| 球被其他物体遮挡 | 检查摆杆上方是否有线缆等遮挡物 |

### 15.7 泰山派摄像头打不开

```bash
# 检查摄像头设备
ls /dev/video*
v4l2-ctl --list-devices

# 检查摄像头是否被其他进程占用

sudo modprobe uvcvideo
```

## 附录B：Keil编译错误速查

| 错误信息 | 原因 | 解决 |
|---|---|---|
| `error: #20: identifier "xxx" is undefined` | 变量或函数未声明 | 检查头文件是否#include |
| `error: L6200E: Symbol xxx multiply defined` | 函数/变量重复定义 | 检查是否多个.c文件有同名全局变量 |
| `warning: #223-D: function "xxx" declared implicitly` | 函数未声明就使用 | 添加函数声明或include对应头文件 |
| `error: L6218E: Undefined symbol xxx` | 链接时找不到函数实现 | 检查.c文件是否加入工程 |
| `No ST-LINK detected` | 烧录器未识别 | 检查USB线和驱动 |
| `Flash Download Failed - Cortex-M3` | 芯片被写保护或SWD被占用 | 用ST-Link Utility解除写保护 |
